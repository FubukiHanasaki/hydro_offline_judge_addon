# Hydro Offline Judge

Hydro 原生 OI 离线赛评测插件。复用 Hydro 账号、比赛、题库和评测队列，将线下收集的代码包预览后一次性导入，自动登记参赛选手并评测。

**版本：0.1.0** · **作者：FubukiHanasaki** · **许可证：AGPL-3.0-or-later**

## 比赛规则

- 每场比赛只能**确认一批正式代码**。预览可以取消、重新上传；确认后不能通过另一个代码包覆盖或追加正式提交。
- 每位选手每道题只允许一份最终源代码，按照 Hydro OI 规则计分。
- 包内所有 UID 都登记为参赛，包括仅登记参赛、没有提交代码的选手。缺交题不伪造提交记录。
- 正式导入评测完成后，参赛选手通过原 Hydro 比赛提交页进行的后续提交均为**订正**：正常评测，但不关联正式比赛，不改变正式成绩、排名或 Rating。
- 确认后中断，应从原批次继续。投递状态不确定时暂停并提示管理员核对，不盲目重复创建评测任务。

首版仅支持 `oi`、已结束、无个人计时、无分组限定且未封榜的比赛；需要专门建立一场没有其他正式提交的比赛。题目需为本地源代码评测题，题目和测试数据必须已在 Hydro 正确配置。不支持 ACM/IOI、答案提交、远程题、二进制代码、多文件项目或自动创建账号。

## 安装

要求 Hydro **5.x（最低 5.0.7）**、Node.js **22.18.0 或更新的兼容版本**、MongoDB **7+**、`@hydrooj/ui-default`，以及已经可以完成普通代码评测的 Hydro 评测机。

使用运行 Hydro 的系统账号，在持久化目录下载本插件，然后执行：

```bash
cd /absolute/path/to/hydro_offline_judge
npm ci
npm run check
hydrooj addon add "$PWD"
hydrooj addon list
```

按已有部署方式只重启 Hydro 网站进程。若 PM2 为 Hydro 指定了独立 Node，安装依赖、检查和注册插件也应使用相同 Node 环境。无需单独运行插件进程，也不需要额外端口。

插件将 Hydro 声明为可选 peer，避免 npm 为插件额外安装另一套 Hydro；运行时仍必须由兼容的 Hydro 宿主加载。不要把 `index.ts` 当作独立程序运行。

### 权限与入口

- 顶部「离线赛评测」，或当前子域的 `/offline-judge`。
- OI 比赛「比赛管理」中的「导入正式代码」。
- 操作者需要有效 Hydro 登录和**当前子域的 `PERM_EDIT_CONTEST`（管理任意比赛）**权限；独立运行时，仅有“编辑自己比赛”或任课教师身份不会自动获得权限。接入新版 SMS 模拟赛管理后，已关联比赛由 SMS 的独立模块权限与实际任教关系共同鉴权，原生 `PERM_EDIT_CONTEST` 不再作为这类比赛的授权依据；参赛班级的教师（全部关联班级都在其任教范围内）或 SMS 管理员可导入，且代码包 UID 必须属于关联班级。管理模板、成员或任教关系变化会在确认、续办及工作进程中重新检查。SMS 模块不可用时，对已关联比赛拒绝导入。
- 每次读写、确认和后台继续执行都检查权限。子域从服务器实际路由上下文取得，不接受请求体中的子域、操作者或选手身份覆盖。
- 选手 UID 必须已存在、账号有效且已经加入比赛所在子域。插件不创建账号、不修改密码、不自动授予成员权限。

反向代理须将 `/offline-judge`、`/offline-judge/*` 和插件静态资源 `/offline-judge/panel.js`、`panel.css` 交给 Hydro，保留原始路径；子域路径 `/d/<domain>/...` 同样交给 Hydro。代理须正确传递外部协议和 Host，否则同源校验会拒绝写请求。不要使用会剥离此路径前缀的 `handle_path`。建议在反向代理层同时限制上传请求体大小（需预留 multipart 开销）。

## 打包格式

ZIP 根目录为 `submissions.csv`，其他文件必须全部被清单引用：

```text
contest.zip
├── submissions.csv
└── code/
    ├── 123/
    │   ├── A.cpp
    │   └── B.cpp
    └── 124/
        └── A.cpp
```

```csv
uid,problem,file,language
123,A,code/123/A.cpp,cc.cc17o2
123,B,code/123/B.cpp,cc.cc17o2
124,A,code/124/A.cpp,cc.cc17o2
125,,,
```

上述 UID 和语言只是示例。请在页面查看服务器实际的**语言 ID**；例如 C++17 O2 可能是 `cc.cc17o2`，不能简单填 `cpp` 代替。页面提供可下载的清单模板。

| 列 | 内容 |
| --- | --- |
| `uid` | 已存在的 Hydro 正整数 UID，不需要用户名或密码 |
| `problem` | 比赛内题号 A、B…，或实际 Hydro 数字题目 ID；数字按实际 ID 解释 |
| `file` | ZIP 内相对路径，与文件名及大小写完全一致 |
| `language` | 当前服务器启用、且题目/比赛/子域允许的语言 ID |

`125,,,` 表示仅登记 UID 125 参赛，没有代码。只登记时后三列须全部留空。每份清单固定四列表头，使用 UTF-8 编码；源代码同样使用 UTF-8。

限制：ZIP ≤10 MB，实际解压内容总计 ≤20 MB，每份代码 ≤128 KB（服务器更低的限制优先），清单 ≤256 KB，每批 ≤500 行、ZIP ≤1500 条目。拒绝加密包、链接、危险路径、大小写重名和清单未引用文件；仅支持普通存储/Deflate ZIP。不上传编译产物、题目数据或学生联系方式。

## 使用步骤

1. 在目标子域建立专用 OI 比赛，配置题目及测试数据，确认普通提交能够正常评测；正式代码在比赛结束后上传。
2. 使用旧版 SMS Rating 时先关闭该场比赛的计分；接入新版 SMS 管理员核验流程的模拟赛可预先标记 Rated，评测完成后再核验发布。已发布评分的比赛需先由管理员撤销本场评分并核验，才能导入新的正式代码包。
3. 进入离线赛评测，选择比赛、上传 ZIP。
4. 预览 UID、账号名、题目、语言、文件及错误；此时不会登记参赛、写入正式提交或启动评测。
5. 解决全部错误后勾选最终代码确认项，点击「确认导入并评测」。
6. 插件先登记全部参赛选手和正式记录，再以低优先级、限速方式投入 Hydro 原生队列。页面持续显示进度，并链接到原生评测记录。
7. 等待「评测完成」，检查正式成绩榜，再按需开启 Rating。
8. 后续选手从比赛提交页提交即为订正，页面明确提示其不计入正式成绩。

确认会重新检查权限、成员关系、已有提交和比赛/题目/语言配置。预览过期或配置变化时需要重新预览。预览 24 小时有效，每名操作者最多保留 5 个有效预览。

## 中断与恢复

- 已确认的批次不能取消、重新上传或换批追加；通过「导入记录」打开原批次继续。
- 普通中断可点击「检查并继续原批次」。正在运行的批次需要心跳失效满两分钟后才允许继续。
- 如果提示“投递状态不确定”，插件不会自动再次入队。先由管理员核对原生记录及评测机状态；必要时使用 Hydro 原生重新评测功能处理**原记录**，再从原批次检查继续。不要删除正式批次锁或直接复制记录。
- 系统错误、取消等基础设施异常不视为有效评测完成；编译错误等选手结果可按正常 OI 规则计分。
- 确认是不可逆业务操作，不承诺跨全部集合的原子事务。通过固定记录 ID、永久比赛批次锁和逐行阶段记录实现防重及可恢复，失败时可能已有部分选手登记或记录建立。

## 数据安全与维护

源码仅在服务器内存解析，并保存到私有 MongoDB 批次集合以支持恢复；不解压到 Web 静态目录，不在网站进程中编译或执行。实际编译和运行依赖 Hydro 已配置的隔离评测机，插件不提供替代沙箱。

预览接口和操作审计不返回/保存代码正文、密码、会话或联系方式。已取消、过期及完成批次清理插件暂存代码；正式代码按 Hydro 原有提交记录政策保存。未完成的正式批次保留暂存代码以供恢复。管理员仍可通过 Hydro 原生权限读取代码。

首版导入维护参赛状态、正式记录、评测队列和比赛成绩，不重放普通网页提交的用户/题目 `nSubmit` 累计计数；因此相关累计提交数可能与新增离线记录数量不同。原生评测结果和比赛成绩是本插件的核对依据。

插件集合为 `offline_judge_jobs`、`offline_judge_rows`、`offline_judge_contests`、`offline_judge_audit`。备份需要同时包含这些集合、Hydro 比赛、参赛状态、提交记录和评测任务；只备份插件目录无法恢复业务。不要单独删除比赛锁集合。

更新前备份数据库与插件清单，然后：

```bash
git pull --ff-only
npm ci
npm run check
```

无正在导入或评测的批次时重启 Hydro。更新或卸载后需验证原生提交行为：**卸载插件会失去订正拦截逻辑**，应保留比赛结束状态，并限制管理人员通过其他工具追加正式提交。第三方插件绕过本插件直接修改数据库不在此保证范围内。

### SMS Rating 互操作

本插件可独立运行；与新版 SMS 联用时，通过比赛 ID 及运行期受控鉴权桥接共享班级范围，不复制学生联系方式或账号密码。SMS 的比赛快照读取需包含 `offline_judge_contests` 未完成批次检查，防止正式记录尚未完整建立时提前结算。没有该兼容检查的旧 SMS，必须始终等本插件显示「评测完成」后再开启计分，不在导入期间操作计分开关。

仅登记参赛但完全未提交代码的选手在 Hydro 中是参赛者；SMS 是否将其计入 Rating 由 SMS 的缺考/无提交规则决定，本插件不伪造零分代码以改变该规则。

## 开发

业务流程位于 `src/service.ts`，ZIP 与清单校验位于 `src/archive.ts`，Hydro 适配边界位于 `src/gateway.ts`。前端、模板和业务模块独立存放。`src/hydro.d.ts` 仅声明使用到的宿主 API，宿主兼容性须另外通过实际 Hydro 集成验证。

测试、截图、日志、合成数据库统一保存在 `.tmp/`，不提交 Git。`npm run check` 检查类型；本地测试夹具存在时可运行 `npm run test:local`。版本号仅在维护者明确要求时变更。
